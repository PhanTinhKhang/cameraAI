## 1. The Core Ecosystem
The project is a real-time emergency detection and dispatch system containing four main components:
1. **ML Service (`ML/`)**: A Python script (`arlert.py`) that captures RTSP/webcam frames, runs YOLOv8 models to detect Accidents, Fires, and Congestion, streams video via local WebRTC (port `8080`), and records 5-second video clips of incidents.
2. **Backend Server (`Arlert_BE/`)**: A FastAPI app (`alert_server.py`) running on port `8000`. It connects to a MongoDB database (`ai_camera`), stores alerts, serves videos statically, broadcasts WebSockets to the frontend, and handles Firebase Push Notifications.
3. **Admin Dashboard (`ai-cam-web/`)**: A React/Vite app running on port `5173`. It connects to `localhost:8000`, receives WebSockets, plays alert videos, manages cameras, and displays volunteer lists.
4. **Volunteer Mobile App (`flutter_app/`)**: A Flutter app for volunteers. It tracks their GPS location, registers their skills/preferences, and receives push notifications when an emergency occurs near them.

## 2. Recent Major Fixes & Architectural Decisions (CRITICAL)
Before you write any code or debug connection issues, you **MUST** know how the network and components are currently wired:

### Local Networking vs. Ngrok
- **The Ngrok Problem:** Originally, the Flutter app and React app used a free ngrok domain that changed every time the user ran `./start.bat`, breaking the frontend and video playback completely.
- **The Fix:** We completely removed the ngrok dependency for local development. 
  - The **React App** now uses `http://localhost:8000` exclusively (because it runs in the laptop's browser).
  - The **Flutter App** uses a dynamic `baseUrl` in `api_service.dart`. For Android Emulators it connects directly to `http://10.0.2.2:8000` (the emulator's localhost loopback). For physical devices, we have hardcoded a **Static Ngrok Domain** (`linoleum-devourer-kindred.ngrok-free.dev`), and updated `run_ngrok.bat` to launch with the `--domain` flag.
  - **Rule:** Do NOT use ngrok URLs in the React frontend. Do NOT use `localhost` in the Flutter app.

### Firebase & Geolocation (Haversine)
- We implemented a **Radius-Based Push Notification System**.
- When the ML service detects an accident, it POSTs to the FastAPI backend.
- The FastAPI backend calculates the **Haversine distance** between the camera's coordinates and every volunteer's GPS coordinates (synced by the Flutter app).
- If the volunteer is within **2.0 km** and their preferences match the alert type (e.g., they opted into "Fire" alerts), the backend triggers a Firebase Cloud Messaging (FCM) push notification using the `firebase-admin` Python SDK.

### User Profiles & Skills
- The `users_col` in MongoDB stores custom volunteer profiles.
- The Flutter App contains a `ProfileScreen` where volunteers select their Skills (e.g., Doctor, Mechanic) and Alert Preferences.
- When an alert triggers and a volunteer clicks "I will help", their specific skill is appended to the `alert.volunteers` array and displayed directly on the React Admin Dashboard.

## 3. History of Fixes & Bugs Overcome (What We Built Together)
To prevent you from repeating past mistakes, here is exactly what we fixed together during the development phase:
- **Flutter Web Google Maps Crash:** We encountered a "Red Screen of Death" (`Cannot read properties of undefined (reading 'maps')`) on Flutter Web because the Google Maps SDK script was missing. We injected `<script src="https://maps.googleapis.com/maps/api/js"></script>` into `flutter_app/web/index.html`.
- **Ngrok HTML Warning Injection:** The React Dashboard originally failed to fetch data over ngrok because the free tier intercepted the first API call with an HTML warning page. We fixed this by injecting the `ngrok-skip-browser-warning: true` header into every `fetch()` request. Later, we removed ngrok entirely for React and routed it to `localhost`.
- **Flutter Video Playback:** Initially, the Flutter app showed a fake black container reading "Live Camera Feed". We fully implemented the `video_player` package and now pass the raw `.mp4` URL straight to a custom `AlertVideoPlayer` widget inside `map_screen.dart`.
- **Flutter Setup & Dependencies:** We had to manually install the Android SDK (`cmdline-tools`), accept licenses (`flutter doctor --android-licenses`), and install `firebase-admin` via pip to get Push Notifications working. Do not attempt to re-install these unless explicitly requested.
- **Flutter Foreground Notifications:** We discovered FCM only shows system popups when the app is in the background. We implemented a `FirebaseMessaging.onMessage.listen` handler in `main.dart` with a `GlobalKey<ScaffoldMessengerState>` to display a top-screen SnackBar immediately if an alert triggers while the volunteer has the app open.
- **Flutter Background Notifications:** FCM was failing to run when the app was fully closed. We registered a top-level `@pragma('vm:entry-point') _firebaseMessagingBackgroundHandler` in `main.dart` and requested explicit notification permissions to ensure background messages arrive perfectly on Android 13+. Furthermore, we later integrated `flutter_local_notifications` and the `coreLibraryDesugaring` build plugin to ensure robust Android background message rendering without crashing.
- **Flutter Emulators Infinite Loading:** Android Emulators (like BlueStacks) without Google Play Services would hang indefinitely on `FirebaseMessaging.instance.getToken()`. We added a `timeout(3 seconds)` bypass to let volunteers log in without hanging. We also added strict 10-second HTTP timeouts in `api_service.dart` and fallback logic for GPS position retrieval, fully stabilizing the app on emulators.
- **Flutter Persistent Login:** The app previously required logging in every single time. We installed `shared_preferences`, cached the `userId`, and now bypass the login screen completely if a user is already active.
- **React Dashboard Re-architecture & Resizing Fix:**
  - Originally attempted to use `react-resizable-panels`, but it fundamentally conflicted with Ant Design's `Layout` and `Content` CSS grids, causing catastrophic map sizing bugs.
  - Reverted to the native Ant Design `<Sider>` + `<Content>` layout, but implemented a custom, robust React `onMouseDown`/`mousemove` drag handle on the sidebar to allow fluid resizing between 250px and 800px.
  - The default sidebar width was increased from `350px` to `400px` for better alert readability.
  - Added a `DatePicker` from `dayjs` so Admins can filter the vast history of alerts.
  - Removed the hardcoded 5-alert limitation to display proper historical queries.
- **React Audio Spam Bug:** The `useAlertSound` hook would randomly trigger sounds because MongoDB WebSocket payloads sometimes toggled between `time` and `_id`. We normalized the ID checking (`alert._id || alert.id || alert.time`) to perfectly prevent false positives.
- **Dashboard Alert Statistics Panel:** We introduced a new `AlertStats` component using `recharts`. It dynamically filters alert history by date (e.g., "7 ngày qua") and by Camera location, calculating Total Alerts, Total Volunteers dispatched, and the total count of **Resolved Alerts** (`Số Cảnh Báo Đã Giải Quyết`).
- **Dashboard Manual Triggers:** Added interactive buttons (Tai nạn, Cháy, Kẹt xe) into the `MapView` to instantly trigger test alerts. This bypasses the ML service entirely, making end-to-end frontend/mobile testing much faster.
- **Critical Reconnection Logic:** Added exponential backoff and "Reconnecting..." overlays to `WebRTCPlayer.jsx`, and auto-reconnect loops to the WebSocket in `useAlerts.js` so the frontend gracefully recovers if the FastAPI backend restarts.
- **Focus View ("Theo dõi") Dashboard:** Implemented a highly interactive `FocusPanel` component that activates when the admin clicks "Theo dõi". It contains a large split-screen displaying the real-time WebRTC feed and a live Google Map of the incident with blue markers representing dispatched volunteers. We built a 3-second polling mechanism to `GET /api/alerts/{id}/tracking` to keep volunteer GPS positions totally live. We had to fix several UI crashes by ensuring `Number(lat)` was properly parsed for Google Maps, and that old legacy alerts missing `alert.type` didn't crash the UI when attempting `.toUpperCase()`.
- **Flutter Background Notifications "Nuclear Option" (Data-Only Payload)**: Many Custom ROM Android devices (Xiaomi, Oppo, Vivo) have aggressive battery managers that silently kill FCM `notification` payloads when the app is swiped away. We fundamentally bypassed this by restructuring the backend's FCM payload in `alert_server.py` to be **100% Data-Only** (`"is_data_notification": "true"`). This forces the Android OS to wake up the Flutter background isolate, which then manually constructs and fires a local system notification using `flutter_local_notifications`, guaranteeing delivery even when fully closed! Note: this relies on the backend securely caching the user's last known GPS location in MongoDB because closed apps cannot emit live GPS.
- **Flutter App Video Playback Retry Loop:** The backend `ffmpeg` subprocess takes ~5 seconds to finish writing and encoding the alert `.mp4`. If a volunteer tapped the push notification immediately, the Flutter `AlertVideoPlayer` would crash or hang because the file wasn't ready. We added a 5-second polling retry loop with a "Video đang được xử lý..." (Video is being processed...) UI spinner in `MapScreen` to gracefully wait for the file to exist.
- **App UI & Mission Enhancements**:
  - Replaced ambiguous "Đang di chuyển" / "Đang đến" statuses with the clearer "Tham gia cứu hộ".

- **Routing API Change (Google Maps to OSRM)**: Replaced the Google Maps Directions API with the open-source OSRM routing API to bypass Google Cloud billing restrictions in Vietnam, restoring the Polyline route drawing in the mission screen.

## 4. How to Run the System
The entire suite is launched via a single batch script:
- Run `./start.bat` in the root directory `d:\cameraAI2`.
- This script spins up 5 command prompts: FastAPI, ML Camera script, React Web UI, Video Cleanup Service, and Ngrok.
- To test the Flutter App, `cd flutter_app` and run `flutter run -d chrome` or run it on an Android Emulator.
